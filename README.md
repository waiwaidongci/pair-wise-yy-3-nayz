# 岩芯样本切片实验室

运行：

```bash
npm start
```

访问 `http://localhost:3025`。支持样本创建、切片任务、步骤记录和交付统计。

测试（自动起停服务、使用临时数据文件，不污染真实数据）：

```bash
npm test
```

## 模块划分

原先所有逻辑挤在 `server.js` 一个文件里，现拆成三个业务模块，入口 `server.js` 只负责启动：

| 模块 | 职责 |
| --- | --- |
| `src/app.js` 请求处理 | HTTP 路由、请求体/请求头解析、错误响应；不含业务规则，不直接读写数据文件 |
| `src/domain.js` 状态重算 | 样本状态重算、交付结论判定、步骤推进、交付快照固化；纯函数，不碰 HTTP 和存储 |
| `src/store.js` 记录存储 | `data/core-slices.json` 的原子读写、串行写队列、乐观版本号、请求编号台账 |

## 并发与一致性约定

- **请求编号**：每个写请求通过 `X-Request-Id`（或 `Idempotency-Key`）请求头携带，也可放在请求体 `requestId` 字段；响应会回显所用编号。浏览器端每次提交生成 UUID，失败后再点同一按钮沿用原编号重试。
- **乐观版本号**：`GET /api/samples` 返回整库 `rev`，每个样本带自己的 `rev`。写请求在请求体带 `expectedRev`：
  - 并发提交时先到的一笔通过版本校验并写入，后到的一笔拿到 `409 version_conflict`（响应给出 `expected`/`current`），客户端刷新后基于新版本重试；
  - 创建样本校验整库 `rev`，样本内的操作校验该样本的 `rev`，互不相关的样本互不阻塞。
- **幂等台账**：存储层维护 `requestLedger`，台账与业务数据在同一次原子写入（临时文件 + rename）中落盘。
  - 同一请求编号重试：直接回放第一次的响应，业务函数不会再执行，**不会重复追加日志/快照**；
  - 写入失败（如磁盘错误）时台账不存在，重试安全，只会追加一次；
  - 同一编号搭配不同请求体返回 `409 idempotency_key_conflict`，防止编号挪用。
- **同一步骤重复提交**：同一切片重复提交当前所处步骤（新请求编号也算），沿用第一次结果，返回 `deduped: true`，不追加记录、不推进版本。

## 交付结论与快照

- 交付结论：样本下所有切片都到“观察”步骤才可交付，否则 `409 not_deliverable` 并列出未完成的切片。
- 交付成功时固化一份不可变快照（交付时间、当时的样本版本号、样本与切片数据全量），存于样本的 `deliverySnapshots`。
- 交付之后若**样本或切片发生变化**（新增切片、步骤推进/回退），交付结论立即失效：`delivery` 回到“未交付”、样本状态按切片重算，并记录失效时间与原因；**历史交付快照保留不动**，可随时在卡片上查看，或通过接口查询：

```bash
curl http://localhost:3025/api/samples/<样本ID>/deliveries
```

旧版数据文件首次读取时自动迁移（补齐 `rev`、`requestLedger`、`deliverySnapshots`）。
